= Licenses and subscriptions 관련 FAQ
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
이 페이지에서는 NetApp Console의 Licenses and subscriptions에 대해 자주 묻는 질문에 대한 답변을 제공합니다. 직접 라이선스, 마켓플레이스 구독, 비공개 오퍼, Keystone 구독 및 청구 기본 설정을 관리할 때 유용한 개념, 결정 사항 및 제약 조건에 중점을 둡니다.



[[overview-and-access]]
== 개요 및 접근 방법

.NetApp Console에서 직접 라이선스, 마켓플레이스 구독, Keystone 구독의 차이점은 무엇입니까?
* *직접 라이선스*는 NetApp에서 구매하며 일반적으로 라이선스 파일, 일련 번호 또는 용량 권한을 사용하여 관리됩니다. 이를 흔히 bring-your-own-license(BYOL)라고 합니다.
* *Marketplace 구독*은 AWS Marketplace, Azure Marketplace 또는 Google Cloud Marketplace를 통해 구매하거나 활성화됩니다. 요금은 클라우드 제공업체를 통해 청구됩니다.
* *Keystone 구독*은 NetApp 사용량 기반 계약입니다. NetApp이 콘솔 계정을 승인하면, 적격 Cloud Volumes ONTAP 구축 환경에서 Keystone을 결제 수단으로 사용할 수 있습니다.


.라이선스 및 구독이 NetApp Console에 자동으로 표시되지 않는 이유는 무엇입니까?
라이선스 및 구독 정보는 콘솔 계정이 NetApp 지원 사이트(NSS) 계정과 연결된 경우에만 자동으로 표시됩니다. 콘솔 계정이 NSS 계정과 연결되어 있지 않으면 라이선스를 수동으로 추가해야 합니다. 사용량, 용량 및 기타 세부 정보도 자동으로 업데이트되지 않습니다. https://docs.netapp.com/us-en/console-setup-admin/task-adding-nss-accounts.html["콘솔 자격 증명에 NetApp 지원 사이트 계정을 추가하는 방법을 알아보세요."^].

.라이선스 및 구독을 보려면 Console 에이전트가 필요한가요?
구독 정보를 보려면 Console 에이전트를 배포해야 합니다. Cloud Volumes ONTAP에 대한 직접 라이선스를 보려면 에이전트도 필요합니다.

.NetApp Console에서 어떤 서비스에 대한 Licenses and subscriptions를 관리할 수 있습니까?
Backup and Recovery, Cloud Tiering, Cloud Volumes ONTAP, Disaster Recovery(BYOL만 해당) 및 Ransomware Resilience에 대한 Licenses and subscriptions를 관리할 수 있습니다.

.NetApp Console에서 라이선스 및 구독을 관리할 수 있는 역할은 무엇입니까?
Licenses and subscriptions 관리자 역할을 가진 사용자는 직접 라이선스를 추가, 편집 및 삭제할 수 있으며, 마켓플레이스 및 Keystone 구독을 연결하거나 연결 해제할 수 있습니다.

해당 보기 권한이 있는 사용자는 Licenses and subscriptions를 볼 수 있지만 변경할 수는 없습니다.

.개요 대시보드에서 새 라이선스 또는 구독을 추가할 수 없는 이유는 무엇입니까?
개요 대시보드는 기존 라이선스 문제를 검토하고 해결하기 위한 것입니다. 직접 라이선스를 추가하려면 *직접 라이선스*로 이동하십시오. 마켓플레이스 구독을 추가하거나 연결하려면 *마켓플레이스 구독*으로 이동하십시오.

.라이선스나 구독에 주의가 필요한지 어떻게 알 수 있습니까?
개요 대시보드의 *조치 필요* 타일은 만료 예정이거나 용량 제한에 도달한 라이선스 및 구독을 알려줍니다. *해결*이 표시되지 않으면 조치가 필요한 문제가 없습니다. *해결*을 선택하면 *라이선스* 또는 *구독* 탭에서 문제를 확인하고 해결할 수 있는 페이지로 이동합니다.



[[direct-licenses-byol]]
== 직접 라이선스(BYOL)

.NSS 계정을 연동하는 것과 라이선스 파일을 수동으로 업로드하는 것의 차이점은 무엇인가요?
콘솔 계정을 NSS 계정과 연결하면 콘솔에서 라이선스를 자동으로 감지하고 업데이트할 수 있습니다. 또한 라이선스를 추가하거나 업데이트하기 위해 일련 번호를 입력할 때도 NSS 계정 연결이 필요합니다.

콘솔이 인터넷에 연결되어 있지 않거나 콘솔 계정이 NSS 계정과 연결되어 있지 않은 경우, NetApp 라이선스 파일을 수동으로 가져와서 업로드해야 합니다. 이러한 경우 콘솔에서 라이선스를 자동으로 조회하거나 업데이트할 수 없습니다.

.Cloud Volumes ONTAP에 대한 용량 기반 및 노드 기반 BYOL 라이선스의 차이점은 무엇입니까?
* *용량 기반 BYOL 라이선스*의 경우, 라이선스는 단일 시스템이 아닌 콘솔 계정과 연결됩니다. 각 시스템에는 고유한 일련 번호가 부여되지만, 동일 계정의 여러 시스템은 공유 용량 풀에서 리소스를 사용합니다.
* *노드 기반 BYOL 라이선스*의 경우, 풀링은 적용되지 않습니다. 각 Cloud Volumes ONTAP 시스템에는 자체 전용 시스템 라이선스가 필요하지만, 기존 시스템을 삭제하면 새 시스템으로 라이선스를 이전할 수 있습니다.


노드 기반 라이선스는 이전 세대 모델입니다. NetApp은 모든 신규 구축에 대해 용량 기반 라이선스를 권장하며, 기존 노드 기반 라이선스는 전환해야 합니다. https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-convert-node-capacity.html["노드 기반 라이선스를 용량 기반 라이선스로 변환하는 방법을 알아보세요"^].

.할당되지 않은 Cloud Volumes ONTAP 라이선스를 다른 서비스로 교환하면 어떻게 되나요?
할당되지 않은 Cloud Volumes ONTAP 라이선스를 교환하면 해당 라이선스가 취소되고 새 서비스(NetApp Backup and Recovery, Data Classification 또는 Cloud Tiering)에 대한 동일한 금액의 라이선스가 생성됩니다.

* HA 쌍에 대한 라이선스는 51 TiB 직접 라이선스로 변환됩니다.
* 단일 노드 라이선스는 32 TiB 직접 라이선스로 변환됩니다.


변환된 라이선스는 기존 Cloud Volumes ONTAP 라이선스와 동일한 만료일을 유지합니다.

.BYOL 라이선스에 대한 요금이 청구되는지, 아니면 PAYGO 마켓플레이스 구독에 대한 요금이 청구되는지 어떻게 알 수 있습니까?
콘솔은 먼저 사용 가능한 NetApp 라이선스를 기준으로 사용량을 청구하려고 시도합니다. 충분한 라이선스 용량이 없는 경우, 연결된 Marketplace PAYGO 구독을 기준으로 사용량을 청구합니다.

용량 기반 라이선스 패키지를 변경해도 사용량에 대한 요금 청구 방식이 NetApp 구매 라이선스(BYOL)인지 마켓플레이스 PAYGO 구독인지는 변경되지 않습니다. BYOL 라이선스를 마켓플레이스 구독으로 또는 그 반대로 변환할 필요가 없습니다.

.마켓플레이스 계약에 포함되지 않은 결제 방식을 선택하면 어떻게 되나요?
마켓플레이스 개인 제안 또는 계약에 포함되지 않은 결제 방식을 선택하면 해당 마켓플레이스 패키지를 사용할 수 없습니다. 사용량은 사용 가능한 경우 NetApp 라이선스에 따라 청구되거나, 대신 PAYGO를 통해 청구됩니다.



[[marketplace-subscriptions-and-private-offers]]
== 마켓플레이스 구독 및 비공개 상품

.하나의 Azure 구독 또는 Google Cloud 프로젝트에 연결할 수 있는 Marketplace 구독은 몇 개입니까?
하나의 Azure 구독 또는 Google Cloud 프로젝트에는 하나의 Marketplace 구독만 연결할 수 있습니다. 동일한 Azure 구독 또는 Google Cloud 프로젝트에서 두 개의 서로 다른 Marketplace 구독을 사용하여 워크로드를 실행하려면 각 구독에 대해 별도의 Console 계정을 두 개 생성해야 합니다.

.Licenses and subscriptions에서 Marketplace 구독을 언제 제거할 수 있습니까?
상태가 *구독 취소됨*인 구독만 삭제할 수 있으며, 삭제하기 전에 관련 설정, 데이터 및 구성을 모두 지우거나 재설정해야 합니다. 구독이 여전히 구성된 상태라면 *삭제* 옵션을 사용할 수 없습니다. link:task-manage-subscriptions.html#remove-a-subscription["구독을 제거하는 방법을 알아보십시오"^].

.프라이빗 오퍼를 두 번 이상 수락하거나 활성화하면 어떤 위험이 있습니까?
프라이빗 오퍼를 여러 번 수락하고 활성화하면 이중 청구가 발생할 수 있습니다. 수락 과정에서 필수 단계를 건너뛰면 청구 오류 또는 활성화 문제가 발생할 수도 있습니다.

.개인 제안의 조건, 가격 또는 세부 정보가 잘못된 것 같으면 어떻게 해야 합니까?
제안 조건, 가격 또는 세부 정보에 불일치가 있거나 어떤 제안을 수락해야 할지 확실하지 않은 경우 제안을 수락하지 마십시오. 진행하기 전에 NetApp 영업 또는 계정 담당 팀에 문의하여 자세한 내용을 확인하십시오.

.수정된 Google Cloud 비공개 제안을 수락하거나 이미 PAYGO 구독을 사용 중인 경우 어떻게 됩니까?
이미 활성 PAYGO 구독 또는 수정된 비공개 오퍼가 있는 경우 수락 단계만 수행하면 됩니다. 이러한 경우 Google Cloud Marketplace는 동일한 목록 내에서 요금제를 업데이트하고 동일한 구독 ID를 유지하므로 콘솔의 구독 연결이 그대로 유지됩니다.

.무료 체험 결제 계정을 사용하여 Google Cloud 비공개 오퍼를 수락할 수 있나요?
아니요. Google Cloud 결제 계정은 무료 체험판이 아니어야 합니다. 무료 체험판 계정으로는 개인 제안을 수락할 수 없기 때문입니다. 무료 체험판 결제 계정을 사용하려고 하면 오류가 발생하여 NetApp 클라우드 팀의 지원이 필요합니다.

.여러 AWS 구독 유형을 사용하거나 목록 간에 마이그레이션하는 경우 이중으로 요금이 청구되나요?
여러 구독 유형을 사용하거나 목록 간에 마이그레이션하는 경우 중복 측정이 발생하지 않습니다.



[[keystone-subscriptions]]
== Keystone 구독

.Keystone 구독을 사용하기 전에 NetApp에서 콘솔 계정을 승인해야 하는 이유는 무엇입니까?
Keystone 구독을 사용하거나 관리하려면 먼저 NetApp에서 콘솔 계정에 권한을 부여해야 합니다. 이 승인을 통해 적격 Keystone 구독을 NetApp Console에서 사용할 수 있게 됩니다. *Welcome to NetApp Keystone* 페이지가 표시되면 해당 페이지의 연락처 지침에 따라 권한 부여를 요청하십시오. link:task-manage-keystone.html#authorize-your-account["Keystone 구독을 위해 계정을 인증하는 방법에 대해 자세히 알아보세요."^].

.Keystone 구독을 연결하면 어떻게 됩니까?
Keystone 구독을 연결하면 해당 구독이 콘솔 조직 또는 계정과 연결되어 새 Cloud Volumes ONTAP 작업 환경을 생성할 때 결제 방법으로 사용할 수 있게 됩니다.

.Keystone 구독은 언제 연결을 해제할 수 있나요?
Keystone 구독은 기존 Cloud Volumes ONTAP 구독에 연결되어 있지 않은 경우에만 연결을 해제할 수 있습니다.

.Keystone 구독의 약정 용량을 변경하려면 어떻게 해야 하나요?
하나 이상의 구독에 대해 요청된 확정 용량을 입력하고 추가 세부 정보를 제출하여 콘솔에서 직접 NetApp에 요청을 보낼 수 있습니다. 이렇게 하면 처리를 위해 NetApp 시스템에 티켓이 생성됩니다.



[[billing-preferences]]
== 청구 기본 설정

."NetApp 라이선스 우선"과 "마켓플레이스 구독 전용" 결제 방식의 차이점은 무엇입니까?
"NetApp 라이선스 우선"은 활성 NetApp 라이선스를 통한 청구를 우선시하며, 해당 용량이 소진되면 연결된 Marketplace 구독으로 사용량이 이월됩니다. "Marketplace 구독 전용"은 NetApp 라이선스를 완전히 우회하여 Marketplace 계약을 통해 모든 청구를 처리합니다. 이는 클라우드 공급업체 청구를 통해 조달을 표준화하는 조직에서 일반적으로 사용됩니다.

.청구 환경설정에서 사용자 지정 CVO 구성을 언제 활성화해야 하나요?
조직에서 다음을 수행해야 하는 경우 사용자 지정 CVO 구성을 활성화하십시오:

* 별도의 사업부나 환경에서 서로 다른 청구 계정을 유지하기 때문에 동일한 클라우드 공급자 내에서 여러 Marketplace 구독을 개별 Cloud Volumes ONTAP 인스턴스에 매핑합니다.
* 하나의 구독을 여러 클라우드 프로젝트에 매핑하십시오.


예를 들어, A 사업부가 하나의 Azure 구독으로 요금을 청구하고 B 사업부가 다른 구독으로 요금을 청구하는 경우, 사용자 지정 CVO 구성을 통해 각 사업부의 Cloud Volumes ONTAP 인스턴스를 해당 사업부의 구독에 매핑할 수 있습니다.

.사용자 지정 CVO 구성을 활성화한 후 비활성화하면 어떻게 되나요?
사용자 지정 CVO 구성을 비활성화하면 사용자 지정 CVO 구성에서 허용했던 인스턴스별 구독 매핑 대신, 다른 데이터 서비스에 사용되는 전역 청구 모드(NetApp 라이선스 우선 또는 마켓플레이스 구독만)로 모든 Cloud Volumes ONTAP 청구가 재설정됩니다.

.독립형 AWS 구독과 NetApp Intelligent Services(NIS) 구독을 모두 보유한 경우 Cloud Volumes ONTAP 용량에 대한 요금을 어떻게 청구해야 합니까?
AWS 계정에서 두 구독 모두 사용 가능한 경우, 결제 기본 설정을 사용하여 Cloud Volumes ONTAP 용량 결제에 사용할 구독을 선택할 수 있습니다. NIS를 통해 이미 결제되는 기존 Cloud Volumes ONTAP 시스템의 경우, 독립형 구독을 추가해도 결제 기본 설정을 업데이트하지 않는 한 결제가 변경되지 않습니다. 독립형 구독이 제공된 후 생성된 새 배포의 경우, 별도로 재정의하지 않는 한 기본적으로 독립형 구독이 용량 결제(Essentials/Freemium)에 사용됩니다. https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html["Cloud Volumes ONTAP 라이선스 패키지에 대해 자세히 알아보세요"^].

.단독 Cloud Volumes ONTAP AWS 구독을 사용하여 Professional 패키지 또는 Backup and Recovery 요금을 청구할 수 있습니까?
아니요. 독립형 Cloud Volumes ONTAP 구독은 용량 기반의 Essentials 및 Freemium 패키지만 지원합니다. Professional 패키지는 지원되지 않으며 계속해서 NIS 구독을 통해 요금이 청구됩니다. 독립형 구독만 연결된 경우 Essentials를 사용하여 Cloud Volumes ONTAP을 배포할 수 있지만 Backup and Recovery를 구성하려면 다른 구독이 필요합니다. https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/concept-licensing.html["Cloud Volumes ONTAP 라이선스 패키지에 대해 자세히 알아보세요"^].

.청구 설정에서 Keystone 필드는 무엇에 사용되나요?
Keystone 필드는 측정된 서비스 사용량을 Keystone 청구 프로필에 연결합니다. *계약 ID*는 NetApp Console의 청구 기록을 Keystone 계약과 연결하고 사용량 보고를 동기화할 수 있게 해주는 고유 식별자입니다. *서비스 범위*는 Keystone 계약에 포함된 서비스 또는 용량 풀을 나열하여 어떤 워크로드 또는 배포가 포함되는지 명확히 하고, 적격 리소스에 대해서만 Keystone을 통해 청구되도록 합니다.
